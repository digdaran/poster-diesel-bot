# DECISIONS.md — текущие решения и допущения

Краткий срез **действующих** решений по проекту (`ТЗ_Raffle_Platform.md` покрывает только §1–7.6 —
модель данных и часть бизнес-правил; всё остальное, включая изменения границ, зафиксировано только
здесь). Проверяй этот файл перед тем, как ввести новую конвенцию или предположить, что то или иное
ограничение ещё действует — многие решения ниже прямо отменяют формулировки ТЗ по прямому запросу
заказчика.

Номера в скобках — ссылки на `DECISIONS_LOG.md`, где лежит полная история/обоснование/разбор
инцидента. В повседневной работе лог читать не обязательно — только когда нужен контекст конкретного
решения.

## Согласовано с заказчиком напрямую (не в ТЗ / отменяет ТЗ)

- **VK-адаптер реализован и активен в проде** наравне с Telegram — единственное исключение из
  раздела ТЗ про функционал, не входящий в объём версии. MAX остаётся заглушкой
  (`channels/max/`, `NotImplementedError`) — не реализовывать без отдельного согласования с
  владельцем продукта (LOG №12, №32, №33; ARCHITECTURE.md §7.1).
- **Интернет-эквайринг (TBank/VTB/Mock) удалён из кода целиком.** Единственный активный способ
  оплаты — `RequisitesQrProvider`: статический QR по банковским реквизитам, без резервирования
  номерков при создании счёта, без вебхуков; подтверждение — только через сверку банковской выписки
  (LOG №37, №44). `PaymentProviderType.MOCK`/`.TBANK`/`.VTB` остаются значениями enum ради чтения
  исторических строк `Payment.provider` — создать такой провайдер через фабрику больше нельзя.
- **Кнопка отмены платежа убрана из ботов (Telegram/VK) полностью.** `payment_service.cancel_payment`
  остаётся в сервисном слое (протестирован), но вызвать его сейчас неоткуда — ни из бота, ни из
  панели (LOG №42, отменяет №29/№30).
- **Лимит покупок — по суммарному количеству, не по факту наличия активной покупки.** Участник может
  копить несколько параллельных неоплаченных счетов, лимит — `MAX_PENDING_TICKETS_PER_PARTICIPANT`
  (`.env`, по умолчанию 20), считается по сумме `quantity` всех `PENDING Payment`/`ManualRegistration`
  глобально по всем розыгрышам и каналам (LOG №45, отменяет №22).
- **Проактивные уведомления backend уходят одновременно во все привязанные каналы участника**
  (Telegram + VK, если оба есть и `messages_allowed`), не в один приоритетный (LOG №43, отменяет
  "один канал" из №33).
- **Терминология пользовательских текстов бота — только «постер»/«экземпляр»/«номер»**, без
  «розыгрыш»/«номерок»/«коллекция»/лотерейной семантики (LOG №35, №41).
- **На розыгрыш можно загрузить несколько цифровых постеров через веб-админку** (не один
  `digital_poster_path` без механизма загрузки, как раньше) — новая таблица `GiveawayPoster`
  (`giveaway_posters`), `POSTER_DIR` (тот же bind-mount паттерн, что `RECEIPTS_DIR`). При выдаче
  участнику после подтверждённой оплаты отправляется один случайно выбранный постер, подпись
  (`digital_poster_caption`) остаётся общей на розыгрыш (LOG №46).
- **Панель «Продажи» показывает живой статус фоновой сверки банковской выписки** (блок
  `BankReconciliationStatusPanel`, не отдельная страница) — каждый тик `bank_reconciliation_service.reconcile()`
  пишет строку в `bank_reconciliation_runs` (включая "нечего сверять"), панель отдаёт последние 20
  тиков + агрегаты за 24ч через `GET /api/bank-reconciliation/status`. Видимость — только
  Administrator/Super Admin (`Permission.VIEW_BANK_RECONCILIATION`), не Operator (LOG №48).

## Технические допущения по умолчанию

- ORM/миграции: SQLAlchemy 2.0 + Alembic, `Mapped[...]` (LOG №5).
- Телефон: нормализация `phonenumbers`, регион `RU`, хранится без `+` (LOG №6).
- JWT: access 15 мин, refresh 30 дней, stateless, инвалидация — только по TTL/`is_blocked` (LOG №7).
- Пароли панели: argon2id (LOG №8).
- Код номерка: `PREFIX-NNNNNN`, 6 цифр (LOG №9). Номер счёта на оплату — отдельный формат/счётчик,
  `PREFIX-NNNNN`, 5 цифр, уникален в рамках розыгрыша, не глобально (LOG №37).
- Деньги: целые копейки везде, рубли — только в UI/отчётах (LOG №10).
- Таймзона: UTC в БД, локальная — в браузере (LOG №11).
- CI отсутствует сознательно — работа напрямую в `main`, зелёный локальный
  `ruff`+`black`+`mypy`+`pytest` обязателен перед каждым пушем (LOG №14).
- QR-платёж: формат ST00012 (ГОСТ Р 56042-2014), байты Windows-1251 (LOG №37).
- Сверка оплаты требует точного совпадения суммы; расхождение подсвечивается в панели «Продажи» и
  приостанавливает TTL-автопросрочку счёта (LOG №38, №39).

## Известные ограничения / осознанно оставленный мёртвый код

- Ветки `reserves_tickets_on_create`/`poll_pending_payment`/`_reconcile_pending_payments` в
  `payment_service.py`/`backend/background/` недостижимы при единственном текущем провайдере —
  оставлены сознательно, не удалялись ради минимального диффа (LOG №44).

  никуда (не в `main2`, не в `main`).** По запросу заказчика вне ТЗ: для розыгрышей с заполненным
  `Giveaway.google_sheet_id` фоновый цикл раз в `GOOGLE_SHEETS_SYNC_INTERVAL_SEC` полностью
